# Обогащение каталога

В Product добавлены необязательные manufacturerPartNumber и endUserRequired.
Артикул производителя не уникален: идентификатором синхронизации остаётся externalItemId.
Поиск поддерживает артикул производителя. Старые товары допускают пустые новые поля.

## Обновление

До запуска новой версии приложения применить только новые столбцы командой
`npx prisma db execute --file prisma/catalog-enrichment.sql --schema prisma/schema.prisma`
в окружении целевой базы, затем `npm run db:generate` и собрать приложение.
SQL идемпотентен и не изменяет существующие значения. Для полной синхронизации схемы
в среде разработки также доступна команда `npm run db:push`.
В проекте нет истории Prisma migrations; Docker-сервис migrate уже использует db push.
Не применять флаг accept-data-loss: новые поля необязательные и не требуют удаления данных.
После обновления запустить штатную синхронизацию ThinkLink — она заполнит новые поля.

## Контент

ThinkLink обновляет название, артикул производителя, требование конечного покупателя,
цену, остаток, категорию и бренд. Описания, фотографии и ProductSpecification при
повторном импорте сохраняются. Не редактировать name как редакционный заголовок:
оно обновляется поставщиком. Для описаний использовать shortDescription и description.

Изображения хранятся в images как JSON-массив URL. Характеристики — в
ProductSpecification с name, value, group и sortOrder. Заполнять их только по
проверенным данным точной модификации; текущая документация API их не предоставляет.
Отдельный редактор контента и дополнительный источник фотографий пока не подключены.

## Проверки

`npm run type-check`, `npm run build`.
Интеграционный `npm run test:thinklink` требует отдельную локальную базу
TEST_DATABASE_URL с именем stp_thinklink_test и применённой актуальной схемой.
Проверяет в том числе одинаковые артикулы у разных товаров, поиск, обновление
новых полей и сохранение редакционного контента.
